## 一、核心问题与哲学

AI 不缺智商,缺的是**关于你的纵向数据**。通用 LLM 无法替你做重大决策,因为它不了解你的处境、压力反应、历史模式。本系统通过持续记录决策 + 回填真实结果,沉淀出 AI 能用来识别你行为模式、并在你下次冲动时拦你的纵向数据。

**设计哲学(来自原始构思):**

1. **信息分层 + 置信度隔离** —— 四层信息物理分开存储:
   - 原始信息:决策人原话,**可能掺假**(美化自己/贬低他人/主观判断)
   - 决策事实:已发生的客观动作,**确凿无疑**
   - 假设推断:决策人假设 + AI 假设,**非对错,待验证**
   - 结果验证:现实结果,**事后回填**(AI 不知道你的世界发生了什么)
2. **日积月累 → 模式识别** —— 决策越多,系统越能识别行为模式
3. **下决策当口拦截** —— 不等回头查,在记新决策的瞬间用历史教训反问

## 二、形态与位置

- **逻辑**:Claude Code skill,装在 `~/.claude/skills/decision-tracker/`
- **数据**:`<data-dir>/`(可直接在 Finder/Obsidian 浏览)
- **触发词**:`记决策` / `记个决策` / `决策跟踪` / `回填` / `decision`

## 三、文件结构

```
<data-dir>/
├── README.md          系统说明 + 哲学
├── LEDGER.md          人类可读索引(一行一决策)
├── index.json         机器可读索引(模式识别用)
├── patterns.md        个人行为模式库(自动累积,拦截弹药库)
├── docs/              本设计文档
└── decisions/
    └── YYYY-MM-DD-<标题>/
        ├── 01-原始信息.md     文件1:逐字记录 + 置信度标注
        └── 02-决策档案.md     文件2:决策事实 / 假设推断 / 结果验证
```

设计点:
- 每个决策一个**子文件夹**,文件名固定 `01-原始信息.md` / `02-决策档案.md`(好预测),日期+标题放文件夹名(好排序)
- 原始信息与决策档案**物理隔离**,体现"原始可能假、决策确凿"的置信度分层

## 四、文件内部结构

### 文件1 `01-原始信息.md`

```markdown
---
decision_id: YYYY-MM-DD-<标题>
created: YYYY-MM-DD
type: 原始信息
---

# 原始信息(可能掺假,谨慎采信)

## 决策人原话(逐字记录,不改写)
> <原话逐字搬运>

## 置信度标注
| 信息点 | 性质 | 置信度 | 备注 |
|--------|------|--------|------|
| ... | 外部观察/二手转述/决策人假设 | 高/中/低 | <风险点> |
```

性质分类:外部观察 / 二手转述 / 决策人假设。
二手转述与主观判定默认低置信度(警惕美化自己、贬低他人)。

### 文件2 `02-决策档案.md`

```markdown
---
decision_id: YYYY-MM-DD-<标题>
created: YYYY-MM-DD
review_due: YYYY-MM-DD       # 验证到期日,B 提醒 + 预留 C 推送
status: 待验证                # 待验证 / 已回填 / 已放弃
tags: [...]
---

# 决策档案

## 一、决策事实(确凿无疑)
- 日期 / 决策 / 参数 / 验证周期

## 二、假设推断(待验证,非对错)
### 决策人的假设
- ...
### AI 的假设(可能与决策人分歧)
- 决策类型判定(如:跟风型决策)
- 风险点
- 若 patterns.md 已有相关模式,直接引用历史

## 三、结果验证(一周后回填,初始留空)
> _等待 <review_due> 回填_
```

回填后第三层补:主要偏差 / 核心教训 / 暴露的个人模式 / 未来规则。

## 五、index.json 结构

```json
{
  "decisions": [
    {
      "id": "YYYY-MM-DD-<标题>",
      "title": "...",
      "created": "YYYY-MM-DD",
      "review_due": "YYYY-MM-DD",
      "status": "待验证",
      "type": "<决策类型>",
      "tags": ["..."],
      "summary_one_line": "...",
      "lesson": null,
      "patterns_hit": ["..."]
    }
  ]
}
```

作用:记新决策时读此文件秒速匹配同 type/tags/patterns_hit 的历史,无需扫全部档案(省 token、快、准)。

## 六、patterns.md 结构(护城河)

```markdown
# 个人行为模式库(回填累积,记决策时用来拦你)

## 模式:<模式名>
- 首次发现:YYYY-MM-DD(<决策>)
- 复现次数:N
- 典型触发:...
- 历史结果:...
- 拦截话术:"..."

## 规则库(回填沉淀的"未来怎么办")
- <规则>(来源:<决策>,YYYY-MM-DD)
```

## 七、三个动作

### 动作 1 —— 记决策(核心)
一句话喂入,skill 自动:
1. 拆原始信息(标置信度)、决策事实、决策人假设
2. 生成 AI 假设(含决策类型判定)
3. **主动拦截**:拿新决策匹配 index.json + patterns.md。命中历史相似决策/已知模式 → 先用历史教训反问,用户回应后才落盘
4. **仅当置信度判断真有歧义**时反问 1-2 句(默认全自动零打断)
5. 生成 2 文件 + 更新 LEDGER.md / index.json

### 动作 2 —— 回填(命门)
- 进 skill 任何操作前,先扫 index.json 中 `review_due ≤ 今天 && status=待验证`,列出到期提醒
- 用户回填 → 补第三层(偏差/教训/模式/规则),status 改 `已回填`
- **把新暴露的行为模式累积进 patterns.md**(拦截能力随之增强)

### 动作 3 —— 查询/复盘(被动)
- "我想做 X,查查类似的" → 检索历史做对比反问
- "我有哪些反复犯的错" → 汇总 patterns.md

## 八、交互原则

- **默认全自动零打断**(符合用户"编码中不要反复问"偏好)
- 两类**高价值打断**例外:(a) 主动拦截甩历史教训;(b) 置信度真有歧义时反问。两者都是给真金白银的信息,不是无聊澄清题。
- 演示样例(如脏脏包)不落盘

## 九、回填触发策略(分阶段)

- **现在(B)**:手动回填 + 进 skill 时自动扫到期提醒。零额外基础设施(Claude Code 不能定时)。
- **预留(C)**:`review_due` 字段已就位,日后接 launchd 到期 macOS 推送时无需改数据结构。

## 十、闭环

记决策 → 读 patterns 拦截 → 落盘 → 一周后回填 → 更新 patterns → 下次拦得更准。
决策越多,系统越懂你。

## 十一、非目标(YAGNI)

- 不做可分发给小白的纯 prompt 版(用户主力在 Claude Code)
- 不做单文件合并(违背置信度物理隔离)
- 暂不接 launchd 定时推送(预留字段,用顺了再接)
- 不做 Web UI / 数据库(纯 .md + .json,Obsidian 可视化够用)
